## 1. BIS CRS (Bureau of Indian Standards — Compulsory Registration Scheme)

### 1.1 Public REST API for Certificate Verification
**Status: NOT AVAILABLE**

- There is **no public REST API** for BIS CRS certificate verification.
- The official portal is a **web-only application** at:
  - **CRS Portal:** https://www.crsbis.in/
  - **BIS Main Portal:** https://www.bis.gov.in/
- Verification is performed manually via the Search Registered Products page by entering the **7-digit R-number** (e.g., R-XXXXXXX) or the **12-digit certificate number** (CM/L-XXXXXXX-XXXX).
- The portal returns HTML pages showing certificate status (Active/Expired/Suspended), brand name, model number, manufacturing address, validity period, and test lab details.

### 1.2 Sandbox or Test Environment
**Status: NOT FOUND**

- No sandbox, staging, or developer test environment was identified.
- BIS does not appear to offer API keys or developer onboarding.

### 1.3 Authentication Method
**Status: N/A (No API)**

- Web portal uses standard username/password authentication for manufacturers applying for registration.
- No OAuth, API key, or token-based authentication for public verification exists.

### 1.4 Queryable Data
Via the web portal, you can search by:
- Registration number (R-number)
- Certificate/License number (CM/L number)
- Product category / IS number
- Manufacturer name

Returned data includes:
- Certificate status (Active / Expired / Suspended)
- Validity date range
- Registered brand name
- Model number(s)
- Manufacturing address
- Test laboratory name (e.g., CPRI, STQC, or other BIS-recognized labs)
- Scope of certification

### 1.5 Documentation & Third-Party Integrations
- **Official docs:** No developer documentation found.
- **BIS Care App:** A mobile app exists for consumers to scan/verify BIS marks, but no public API documentation.
- **Consultants:** Numerous compliance consultants (Agile Regulatory, ElitasRCS, Corpseed, etc.) offer manual verification services but do not expose APIs.

### 1.6 Technical Integration Recommendation
If you need to verify BIS CRS certificates programmatically, the only viable approach is **web scraping** the crsbis.in search results (with appropriate rate limiting and compliance with Terms of Service). There is no structured data export (JSON/XML) offered by BIS.

## 2. CPCB EPR Portal (Central Pollution Control Board — Extended Producer Responsibility)

### 2.1 APIs for Producer Registration Lookup
**Status: NOT AVAILABLE**

- There is **no public REST API** for looking up producer EPR registrations.
- The CPCB manages sector-specific centralized portals:
  - **Plastic EPR:** https://eprplastic.cpcb.gov.in/
  - **E-Waste EPR:** https://eprewaste.cpcb.gov.in/ (inferred)
  - **Battery Waste EPR:** A dedicated battery portal exists under the CPCB centralized system.
- All portals are **web form-based** with manual login (GST-based authentication + OTP).

### 2.2 APIs for EPR Credit Reconciliation
**Status: NOT AVAILABLE**

- EPR certificates are generated by registered recyclers and traded on the portal.
- The certificate marketplace is **web-based only**; no API for automated purchasing or balance queries was found.
- CPCB determines price floors/ceilings for EPR certificates every 6 months.

### 2.3 CSV/Excel Upload Automation
**Status: PARTIALLY AVAILABLE (Plastic EPR Only)**

- For **Plastic Waste EPR**, CPCB provides a **desktop BOT tool** (CPCB-BOT(v1).zip) that enables bulk upload of invoices:
  - Downloadable from the portal under Bulk Upload -> PIBO
  - Uses Excel templates (SalesData.xlsx, ProcurementData.xlsx)
  - Requires arranging invoice PDFs in specific folders
  - The BOT automates browser interaction, login (credentials + OTP), and file upload
  - **This is RPA-style automation, not a REST API.**
- **For Battery Waste EPR:** No bulk upload tool was explicitly documented in public sources. Returns appear to be filed manually via web forms.

### 2.4 Known Integration Patterns
- **Manual workflow:** Register -> Upload documents (GST, PAN, CIN, IEC) -> Declare battery sales -> File quarterly/annual returns -> Purchase EPR certificates from recyclers.
- **No webhooks, no callbacks, no REST endpoints** for external systems.
- EPR registration approval takes **20-45 working days**.

### 2.5 Technical Integration Recommendation
For battery EPR, the only automation path today is **browser automation** (Selenium/Playwright) or RPA to interact with the portal. For plastic EPR, the CPCB-BOT can be leveraged but requires Windows desktop execution and manual OTP entry.

## 3. EU NANDO (New Approach Notified and Designated Organisations)

### 3.1 Public API Endpoint
**Status: NO OFFICIAL REST API — Web Application with Scrapable Data**

- **Legacy URL:** http://ec.europa.eu/growth/tools-databases/nando/index.cfm
- **Current URL (Single Market Compliance Space):** https://webgate.ec.europa.eu/single-market-compliance-space/notified-bodies
- **Deep links:**
  - By Country: https://webgate.ec.europa.eu/single-market-compliance-space/notified-bodies/by-country
  - By Legislation: https://webgate.ec.europa.eu/single-market-compliance-space/notified-bodies/by-legislation
  - Free Search: https://webgate.ec.europa.eu/single-market-compliance-space/notified-bodies/free-search
  - Filtered Lists (example for MDR): https://webgate.ec.europa.eu/single-market-compliance-space/notified-bodies/notified-body-list?filter=legislationId:34,bodyTypeId:3,notificationStatusId:1

### 3.2 Data Format
**Status: HTML / JavaScript-rendered SPA — No native JSON/XML feed**

- NANDO is now a **Single Page Application (SPA)** rendered in the browser.
- It does **not** expose a public JSON or XML API.
- Data includes:
  - Notified Body ID (4-digit number, e.g., NB 0123)
  - Name and address
  - Country
  - Legislation scope (MDR, IVDR, RED, LVD, EMC, Machinery, PPE, CPR, etc.)
  - Notification status (Active / Suspended / Withdrawn)
  - Scope codes (e.g., MDA 0101, MDA 0102)
  - Contact details (email, website, phone)
- The database is refreshed **daily**.

### 3.3 Query by Notified Body Number
- You can construct filtered URLs using query parameters:
  - legislationId — maps to directive/regulation
  - bodyTypeId — type of body
  - notificationStatusId — 1 for active
  - organizationRefeCd — for direct body lookup (NANDO_INPUT_XXXXX)
- Example direct body link:
  https://webgate.ec.europa.eu/single-market-compliance-space/notified-bodies/notifications?organizationRefeCd=NANDO_INPUT_244583&filter=notificationStatusId:1

### 3.4 Third-Party Scraping Solutions
- **Apify Actor — NANDO Notified Bodies Monitor:** https://apify.com/great_pistachio/nando-notified-bodies-monitor
  - Price: 9/month or /run
  - Extracts structured JSON with fields: nbId, name, country, legislation, status, scopeCodes, email, website, sourceUrl
  - Supports change detection and webhooks
- **GitHub — Open Register Scraper:** https://github.com/register-dynamics/notified-body-registers
  - Ruby-based scraper that outputs RSF and SQLite
  - MIT Licensed; data copyright EU 1995-2018

### 3.5 Technical Integration Recommendation
The most reliable programmatic access is via **Apify scraping actor** or building a custom Puppeteer/Playwright scraper against the SPA. The EU does not block scraping for transparency purposes (public government database), but rate limiting should be respected.

## 4. UN38.3 Test Labs & Report Verification

### 4.1 Central Registry of UN38.3 Test Reports
**Status: DOES NOT EXIST**

- There is **no central global registry** of UN38.3 test reports.
- UN38.3 is defined in the **UN Manual of Tests and Criteria**, Part III, sub-section 38.3.
- Enforcement is via **IATA DGR** (Dangerous Goods Regulations) and **ICAO TI** (Technical Instructions for Safe Transport of Dangerous Goods by Air).
- Test reports are issued by individual **accredited third-party laboratories**.

### 4.2 How UN38.3 Reports Are Verified in Practice
1. **Direct lab verification:** Contact the issuing lab (e.g., SGS, TUV SUD, UL, Intertek) with the report number and ask them to confirm authenticity.
2. **Manufacturer self-publication:** Major brands (HP, Panasonic, Microsoft, Dell) publish UN38.3 Test Summaries on their websites for lookup by model number.
   - HP: https://sustainability.ext.hp.com/en/support/solutions/articles/35000145561
   - Panasonic: https://industrial.panasonic.cn/index.php/ww/downloads/battery-test-summary
3. **Airline/forwarder audit:** Carriers (DHL, FedEx, airlines) require the shipper to provide the report; they do not query a central database.
4. **Amazon/compliance audit:** E-commerce platforms require sellers to upload the UN38.3 Test Summary PDF; no automated API verification exists.

### 4.3 Known APIs or Verification Methods
**Status: NONE FOUND**

- No REST API exists for UN38.3 report lookup.
- No ICAO/IATA central database for test report numbers.
- Verification is **document-based and manual** (PDF review, lab contact, manufacturer lookup).

### 4.4 Accredited Labs (Examples)
- SGS
- TUV SUD
- UL Solutions
- Intertek
- Bureau Veritas
- DEKRA
- China National Accreditation Service (CNAS) labs

### 4.5 Technical Integration Recommendation
For a battery passport platform, UN38.3 verification can only be done by:
1. **Storing the PDF** and metadata (report number, lab name, test date, model number) in your system.
2. **Cross-referencing** against manufacturer-published test summary pages where available.
3. **Manual spot-check** by contacting the issuing lab for high-risk transactions.

## 6. EU Battery Passport Registry APIs (Pilot / Pre-Production)

### 6.1 Regulatory Timeline
- **EU Battery Regulation (2023/1542):** Entered force 17 August 2023
- **Digital Battery Passport mandatory from:**
  - **18 February 2027:** Industrial batteries >2 kWh, EV batteries, LMT batteries
  - **18 August 2028:** Portable batteries of general use
- **QR Code requirement:** Permanently attached, encoding a **GS1 Digital Link URL** that resolves to the Battery Passport data record.

### 6.2 Pilot / Pre-Production APIs
**Status: NO PRODUCTION API YET — Standards & Reference Implementations Exist**

- **CIRPASS / CIRPASS-2 (EU-funded projects):**
  - CIRPASS-2: EUR 12.5M project running May 2024 – April 2027
  - 13 pilot deployments across textiles, electronics, tires, construction
  - Battery sector pilots included
  - **Website:** https://cirpass2.eu/
  - **Output:** Roadmaps, data models, interoperability frameworks — but no public production API endpoint.

- **BatteryPass Consortium:**
  - Developed open-source reference implementation for Digital Battery Passport
  - Based on **W3C Verifiable Credentials Data Model** + **GS1 Digital Link** standard
  - **Technical Guidance:** Published March 2024
  - **Data Model GitHub:** https://github.com/batterypass/BatteryPassDataModel
  - **Standard:** DIN DKE SPEC 99100:2025-02
  - **Resolver:** GS1 Digital Link resolver concept (QR -> URL -> JSON-LD data)

- **Global Battery Alliance (GBA):**
  - Battery Passport framework
  - **Whitepaper:** https://www.globalbattery.org/
  - Supports EU Battery Regulation data attributes

### 6.3 Actual API Endpoints
**Status: NONE IN PRODUCTION**

- No live, public EU Battery Passport registry API exists today.
- The system architecture is expected to be:
  - **Decentralized / federated:** Each manufacturer hosts their own Battery Passport data
  - **Discovery via GS1 Digital Link:** QR code -> GS1 resolver -> manufacturer endpoint
  - **Data exchange protocol:** Likely based on GAIA-X, NGSI-LD, SSI (Self-Sovereign Identity)
  - **Access control:** Role-based (public data + restricted commercial data)

### 6.4 Technical Integration Recommendation
For pre-2027 readiness:
1. Implement **GS1 Digital Link URL generation** for battery QR codes.
2. Study the **BatteryPass GitHub data model** to structure your internal battery passport data.
3. Prepare a **JSON-LD / Verifiable Credentials** endpoint to serve battery passport data.
4. Monitor **CIRPASS-2** and **EU Commission implementing acts** (expected 2025) for finalized technical specifications.

## 9. Honest Assessment of Gaps

1. **BIS CRS:** The biggest gap. Indias mandatory certification scheme for electronics/batteries has zero machine-readable public verification. Every verification is a manual web search.
2. **CPCB EPR:** Similarly manual. The battery waste portal is a black box with no API, no bulk upload tool (unlike plastic), and no webhook notifications.
3. **NANDO:** The EU has modernized the frontend to a SPA but has not exposed a public API. Scraping is technically feasible and legally tolerated (public transparency database).
4. **UN38.3:** A global safety standard with no global registry. This is a significant trust gap — anyone can forge a PDF, and there is no quick way to verify it programmatically.
5. **EU Battery Passport:** The standards and reference implementations are mature, but production APIs will not exist until manufacturers deploy them in 2027. There is no central EU BatteryPass API to query today.
6. **Third-party aggregators:** The market for regulatory certificate verification APIs is immature. Services like RegTechAPI.in prove it is possible for identity/compliance data, but no one has done it for product safety certificates at scale.

## 10. Recommended Technical Strategy for ExportReady

### Immediate (2026)
- **BIS CRS:** Build a lightweight scraper for crsbis.in to verify R-numbers. Cache results aggressively.
- **CPCB EPR:** Store EPR registration numbers and certificate PDFs as document evidence. Set manual review reminders for quarterly/annual filing deadlines.
- **NANDO:** Use the **Apify NANDO actor** ($5/run) or build a monthly Puppeteer scraper to keep a local cache of notified bodies by legislation.
- **UN38.3:** Store PDFs and metadata. For high-value verifications, build a request verification workflow that emails the issuing lab.
- **India Stack:** Integrate **API Setu** for PAN, GST, CIN verification to auto-populate and validate manufacturer/importer business details.

### Near-term (2026-2027)
- **EU Battery Passport:** Implement a **GS1 Digital Link** resolver endpoint in your platform. Follow the BatteryPass GitHub data model. Ensure your database schema can accommodate the EU Battery Regulation Annex XIII data attributes.
- **Automation:** Explore RPA (Robocorp, UiPath, Playwright) for CPCB EPR filing automation if transaction volume justifies it.

### Long-term (2027+)
- **Battery Passport Interoperability:** Once EU Battery Passport goes live, your platform should be able to resolve QR codes to manufacturer-hosted passport data and validate the JSON-LD structure against the DIN DKE SPEC 99100 schema.
- **Advocacy:** Consider engaging with BIS and CPCB through industry associations to advocate for API-first portal designs (following API Setus model).
